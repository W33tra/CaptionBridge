# CaptionBridge

Минимальный Windows-прототип, который передаёт в Google Chrome Live Caption тестовый PCM-поток или звук выбранного Windows-приложения.

Требования: Windows 10 build 20348 или новее, Python 3.10+, Google Chrome и .NET 8 SDK. .NET нужен для сборки маленького helper-компонента, работающего со штатным Windows Process Loopback API.

## Запуск

```bat
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

**Внимание:** команда `python main.py` автоматически откроет новую вкладку Google Chrome. При первом запуске Windows SAPI создаст `audio\test_audio_ru.wav` с тестовой русской речью. Сервер запустится на `http://127.0.0.1:17321`, найдёт установленный `chrome.exe` и откроет страницу именно в Google Chrome. Уже работающий Chrome получит новую вкладку; другие браузеры не закрываются.

Исследовательская версия запускается командой `python main.py`: на ней доступны Яндекс-эксперимент и диагностические кнопки. Отдельная предрелизная версия запускается командой `python prerelease.py`; она сразу открывает пользовательский экран без Яндекса и диагностических элементов. В ней есть нейтральная проверочная запись `audio\caption_check_ru.wav`. Оба варианта используют один порт и поэтому запускаются только по отдельности.

## Сборка предрелизного EXE

Сценарий `build_prerelease.ps1` публикует оба .NET-компонента для `win-x64` в self-contained режиме и упаковывает их вместе с Python, веб-интерфейсом и аудиозаписью:

```powershell
.\build_prerelease.ps1
```

Результат: `dist\CaptionBridge-Prerelease.exe`. Встроенную проверку без открытия браузера можно запустить командой:

```powershell
.\dist\CaptionBridge-Prerelease.exe --self-check
```

Обычный запуск EXE автоматически открывает новую вкладку Google Chrome. Файл пока не имеет цифровой подписи, поэтому Windows SmartScreen может показать предупреждение для неизвестного издателя.

## Проверка

1. В Chrome откройте **Settings → Accessibility → Live Caption** и включите Live Caption.
2. Запустите `python main.py`. Chrome откроется автоматически.
3. Включите звук в целевом приложении и нажмите **Обновить список приложений**.
4. Выберите приложение и нажмите **Запустить субтитры для выбранного приложения**.
5. Проверьте, появляются ли в Chrome автоматические субтитры, затем раскройте **Отдельный оверлей субтитров** и нажмите кнопку открытия отдельного окна.
6. Окно оверлея можно перемещать и растягивать мышью. Кнопка **Остановить текущий поток** завершает захват, а **Закрыть оверлей** закрывает только дополнительное окно.
7. Кнопка **[1] Тестовый поток** запускает диагностический WebSocket-тест с русской речью, **[2]** воспроизводит тот же WAV через обычный `<audio>`, а **[3]** позволяет выбрать собственный файл.

После закрытия последней вкладки CaptionBridge сервер автоматически завершится через 3 секунды. Небольшая задержка позволяет обновлять страницу без остановки программы. Сервер также можно остановить вручную сочетанием `Ctrl+C` в консоли.

Чтобы не слышать второй экземпляр звука, можно выключить звук именно у вкладки CaptionBridge средствами Chrome. Live Caption обычно продолжает получать медиапоток до финального вывода громкости, но это поведение Chrome и оно может меняться между версиями.

## Отдельный оверлей

Раздел **Отдельный оверлей субтитров** создаёт второе стабильное окно поверх остальных окон и дублирует в него готовый текст Chrome. Оно первоначально появляется наверху по центру, чтобы его не закрывала нативная плашка Chrome. Окно регулярно подтверждает свой уровень `TopMost`, поэтому активация целевого приложения не должна отправлять его на задний план.

Ширину, высоту (от 50 пикселей), размер шрифта и непрозрачность можно применить к уже открытому окну отдельной кнопкой без перезапуска. Перемещение и ручное растягивание мышью также поддерживаются.

Эти четыре параметра представлены ползунками. После открытия оверлея они применяются во время движения с ограничением частоты запросов; при закрытом оверлее ползунки только задают значения для следующего запуска.

Список шрифтов применяется так же без перезапуска. Вариант **Как в Chrome** повторяет штатную цепочку Live Caption: `Roboto`, при его отсутствии `Arial`, затем системный `Segoe UI`. Chrome также может использовать пользовательский шрифт, заданный в его настройках специальных возможностей.

Свой шрифт можно добавить непосредственно на странице из файла `.ttf` или `.otf`. Файл копируется в `%LOCALAPPDATA%\CaptionBridge\fonts`, появляется в общем списке и затем сохраняется в именованных профилях. Сам файл шрифта должен разрешать такое локальное использование.

У окна нет заголовка: его можно перетаскивать за любую внутреннюю область, а изменять размер — за невидимую полосу шириной 8 пикселей вдоль краёв и углов. Закрывается оно кнопкой на странице CaptionBridge или вместе с сервером.

Режим **Пропускать щелчки мыши сквозь оверлей** делает окно некликабельным: игра получает щелчки так, словно оверлея нет. Пока этот режим включён, само окно нельзя перетащить или растянуть — режим нужно отключить на странице CaptionBridge.

Именованный профиль сохраняет фактические координаты и размер уже расположенного оверлея, шрифт, прозрачность, режим щелчков и выбранное положение штатного окна Chrome. Например, можно сохранить профиль **Дота**, а затем одной кнопкой вернуть всю раскладку. Профили хранятся локально в текущем профиле браузера.

После запуска и каждого применения настроек координаты проверяются относительно рабочей области ближайшего монитора. Кнопка **Вернуть оверлей на экран** повторно применяет настройки и возвращает окно, если оно было случайно перетащено за границу.

При ручном растягивании окна его фактическая ширина и высота автоматически возвращаются в ползунки на странице. Там же показываются текущие координаты; поэтому сохранённый профиль получает именно видимый размер, а не старые значения настроек.

Оверлей сохраняет визуальные разрывы строк, полученные от Chrome, выравнивает текст влево и размещает свежие строки снизу. Если весь распознанный текст не помещается, старые строки удаляются сверху первыми; слишком длинная последняя строка сокращается с начала. Расчёт повторяется при изменении размера окна или шрифта.

Распознавание по-прежнему выполняет только Chrome. Нативный компонент читает уже готовый текст из элементов доступности окна Live Caption и показывает последние фрагменты в оверлее. Поддерживаются как прежняя структура `AnnounceTextView`, так и новая `CaptionBubbleLabel`. Текст не передаётся серверу и не записывается в терминал. Нативную плашку Chrome нужно оставить открытой, но её можно не перемещать, оставить видимым один пиксель у правого края или полностью убрать за правый край. CaptionBridge меняет только координаты, не размер плашки, и регулярно возвращает выбранное положение, если Chrome его сбрасывает. При штатном закрытии оверлея плашка возвращается на экран.

При закрытии последней вкладки CaptionBridge оверлей завершается вместе с сервером. Его также можно закрыть отдельной кнопкой или обычным крестиком окна.

## Яндекс Браузер — эксперимент

Кнопка **Открыть эксперимент в Яндекс Браузере** открывает страницу только после явного нажатия. В Яндекс Браузере PCM направляется не прямо в аудиовыход, а в живой HTML5-видеоплеер с техническим видеорядом.

После запуска выбранного приложения наведите указатель на видеоплеер и проверьте, предлагает ли браузер включить субтитры. Если доступна кнопка выносного видео, окно можно разместить поверх игры и изменить его размер. Текущий вариант с программным `MediaStream` не вызвал плашку субтитров при ручной проверке. Отдельный будущий эксперимент — передача потока в нормальном медиаконтейнере через HTTP/MediaSource, как это делают обычные видеоплееры и трансляции.

## Что проверяет прототип

Рабочая цепочка для выбранного приложения:

```text
Windows audio session → Process Loopback Capture → Python → WebSocket
→ Web Audio API → Chrome audio pipeline → Live Caption
→ Windows UI Automation → CaptionBridge overlay
```

Диагностическая цепочка:

```text
test_audio_ru.wav → Python PCM chunks → WebSocket → Web Audio API
→ Chrome audio pipeline → Live Caption
```

Обычный `<audio>` с тем же файлом служит контрольной группой. Веб-страница не имеет API Chrome Live Caption; готовый текст для оверлея читает отдельный Windows-компонент через интерфейс доступности.

Нативный helper собирается автоматически при первом чтении списка приложений. Он перечисляет активные render-сессии через `IAudioSessionManager2` и захватывает выбранный PID вместе с дочерними процессами через `ActivateAudioInterfaceAsync`.

## Ограничения MVP

- Распознавание выполняет только Chrome Live Caption.
- Тестовая фраза русская. CaptionBridge выбирает установленный русский SAPI-голос, а при его отсутствии использует системный голос по умолчанию; качество произношения в таком случае зависит от Windows.
- Некоторые приложения со сложной аудиоизоляцией могут возвращать тишину через Windows process loopback; это ограничение нужно проверять отдельно для конкретного приложения.
